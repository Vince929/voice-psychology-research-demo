# 焦虑人群语音心理支持 Agent

请实现一个面向成年焦虑人群的 AI 心理支持 Agent。用户登录后，可以通过文字或语音与 Agent 进行多轮交流。Agent 应根据用户当前表达的焦虑程度、沟通偏好和安全风险选择沟通策略，并使用适合的语速、语气和停顿进行语音回复。会话结束后，系统应生成简短总结和下一步行动建议。

> **产品边界**：本系统是非医疗性质的辅助性心理支持工具，不得声称能够诊断或治疗焦虑症，不得替代心理咨询师、精神科医生或紧急援助服务。

## 一、时间与规则

- 开发包括编码、测试、文档和演示准备。
- 可以联网，使用任意 IDE、AI Coding 工具、基础库及外部 AI 服务。
- 允许复用你自己的 voice-psychology-research-demo，但必须列出原有功能、本次复用部分以及本次新增或修改内容。
- 前端可选择 Web 或 React Native，不要求同时实现两端。
- 本地可运行即可，不要求公网部署；不考察复杂视觉设计。
- 不得直接使用一个成熟心理咨询产品或完整开源项目作为核心实现。

## 二、必须完成的产品闭环

登录 → 创建会话与设置偏好 → 文字或语音输入（文字及语音均需支持）→ 状态与风险判断 → 选择支持策略 → 生成文字回复 → 自适应语音播放 → 保存上下文 → 结束会话 → 生成并查看总结

## 三、必做功能

### 1. 简化账户与数据隔离

- 实现用户名或邮箱加密码登录，以及退出登录。
- 密码不得明文保存。
- 至少提供两个可用于验收的测试账户。
- 用户只能访问自己的会话和消息；服务端必须实施鉴权，不能只在前端隐藏数据。
- 不要求注册、邮箱验证、找回密码、第三方登录或后台权限系统。

### 2. 会话偏好

创建会话时，至少收集：

- 当前主要困扰，例如工作、学习、人际关系等等；
- 期望的表达方式：温和陪伴 或 简洁直接；
- 是否播放语音回复。

不要求实现完整心理量表。

### 3. 多轮文字与语音对话

- 用户可以发送文字。
- 用户可以录制或上传一段语音，由 ASR 转写为文字。
- 传递给后续处理的信息，可不仅限于文字本身，可包括例如语气语速等语音中的各类其他信息。
- Agent 结合本次会话上下文生成回复。
- Agent 的文字回复可以通过 TTS 播放。
- 同一会话至少可以连续完成 5 轮对话。
- 页面刷新或重新登录后，仍可查看该用户的历史会话和消息。

本题采用一问一答的轮次式语音交互，不要求实时双工语音、流式 ASR、流式 LLM 输出、用户讲话打断 Agent 或长时间连续录音。

### 4. 状态判断与支持策略

每轮回复前，系统必须生成一份经过 Schema 校验的结构化策略记录。结构可自行调整，但至少表达以下信息：

```json
{
  "anxiety_level": "low | moderate | high | uncertain",
  "risk_level": "normal | ambiguous | high",
  "observed_signals": ["仅引用用户实际表达中的证据"],
  "support_goal": "本轮希望达成的目标",
  "technique": "validation | clarification | grounding | reframing | action_planning | safety_escalation",
  "technique_reason": "选择该策略的简明、可审计理由",
  "response_constraints": {
    "max_sentences": 3,
    "ask_one_question_only": true
  },
  "voice_profile": "calm_slow"
}
```

- LLM 输出字段缺失、类型错误或枚举值非法时，不能直接进入正常业务流程。
- `observed_signals` 必须来自用户的实际表达，不得凭空推断事实。
- 界面只展示简明决策依据，不要求也不应展示模型原始 Chain of Thought。

至少实现以下四种支持路径：

**A. 情绪确认与澄清**

- 适用于一般担忧且用户仍可正常沟通的情况。
- 承认感受并询问具体诱因，不立即输出大段通用建议。

**B. 即时稳定**

- 适用于明显紧张、心跳加快、思绪混乱或无法接受长篇分析的情况。
- 使用短句，一次只提供一个简单步骤。
- 可使用 grounding、注意力定位或简短呼吸引导，但不得强迫用户接受。

**C. 认知与行动整理**

- 帮助用户区分事实、推测和可控制事项。
- 仅给出一至两个现实可行的小步骤。
- 不得保证某种方法一定有效。

**D. 安全分流**

- 用于明确的自伤、自杀风险，或用户要求诊断、药物剂量、停药建议等情况。
- 必须跳过普通心理支持流程，执行固定的安全响应。

README 中需简要说明这些策略参考了哪些方法（例如支持性倾听、CBT、grounding），以及适用边界。

### 5. 三档风险处理

| 风险级别 | 系统行为 |
|---|---|
| normal | 进入正常心理支持策略 |
| ambiguous | 暂不继续一般建议，先提出一个简洁、直接的安全确认问题 |
| high | 停止普通对话流程，进入固定安全分流 |

- 安全判断至少包含确定性规则或等效防线，以及经过校验的结构化判断和固定兜底回复。不得将安全判断完全交给普通对话 Prompt。

高风险响应必须：

- 说明 AI 的能力边界，不作诊断；
- 鼓励用户联系专业人员；
- 紧急风险下建议立即联系当地紧急服务或可信赖的人；
- 不提供药物剂量、停药方案或保证性承诺；
- 将该轮记录为 `safety_escalation`。

### 6. 自适应语音回复

至少实现三种可以实际播放、且参数可验证的语音配置：

| 配置 | 适用情况 | 要求 |
|---|---|---|
| calm_slow | 当前明显紧张 | 较慢语速、稳定或柔和语气、更长停顿、较短回复 |
| warm_normal | 一般焦虑 | 温和、正常语速，允许适度确认和澄清 |
| concise_direct | 状态相对稳定且偏好直接表达 | 减少套话，正常或略快语速，直接提出下一步 |

语音配置的选择遵循以下优先级：**安全要求 > 当前状态 > 用户表达偏好 > 默认设置**

- 每轮记录并展示实际传给 TTS 的参数，例如 `rate`、`pitch`、`volume`、`style`、`pause` 或 SSML。
- 仅修改页面标签、但实际 TTS 参数始终相同，不算完成。
- 不得仅根据性别、年龄、职业等身份标签进行刻板化的语音或策略判断。

### 7. 用户反馈影响后续策略

系统需要处理用户对方法的明确拒绝。例如：

> “我不喜欢呼吸练习，请换一种方式。”

系统应当：

- 记录该会话中的偏好；
- 后续不再重复推荐被拒绝的方法；
- 选择其他适用策略；
- 在策略观察面板中说明本轮避开了什么及原因。

### 8. 会话总结与历史记录

用户结束会话后，生成并保存：

- 本次主要困扰；
- 用户实际提到的关键感受或身体反应；
- 本次采用过的支持策略；
- 用户明确拒绝或不喜欢的方法；
- 双方确认的一个下一步行动；
- 会话风险级别及是否触发过安全分流；
- 非诊断声明。

总结不得凭空补充用户没有表达过的事实或未确认的行动计划。

### 9. 策略观察面板

聊天页面需提供一个简单的测试面板，显示：

- 当前 `anxiety_level` 和 `risk_level`；
- `observed_signals`；
- 本轮采用的 `technique`、`support_goal` 和 `technique_reason`；
- 当前 `voice_profile` 及实际 TTS 参数；
- 是否触发安全确认或安全分流。

## 四、必须提供的测试

至少编写以下五个自动化测试，其中至少三个必须是可实际运行、带有效断言的服务端测试：

1. 普通焦虑输入能够选择一种正常支持策略。
2. 模糊风险输入进入安全确认流程。
3. 明确高风险输入一定进入 `safety_escalation`。
4. 用户拒绝一种方法后，后续轮次不再选择该方法。
5. 账户 A 无权读取账户 B 的会话。

## 五、外部服务规则

- ASR：可复用原项目，也可以做新的。
- LLM：必须至少提供一条真实可运行的调用链路。
- TTS：必须至少提供一条真实播放链路，并证明不同语音配置使用了不同参数。
- 安全分流、账户鉴权和数据隔离不得 Mock。
- 策略选择不得通过精确匹配题目中的测试句子来硬编码完整答案。
- 如果外部服务临时不可用，应显示明确错误；不得把失败伪装成成功。

## 六、验收演示

提交后需要现场演示。测试输入可能与下面示例不同，但会覆盖相同类型：

1. 一般焦虑：验证是否先确认和澄清，而不是立即输出大段建议。
2. 明显紧张：验证即时稳定策略、短回复和 `calm_slow` 的实际参数。
3. 偏好记忆：用户拒绝一种方法后，验证后续策略是否改变。
4. 模糊风险：验证系统是否先提出安全确认问题。
5. 明确高风险：验证系统是否跳过普通回复并进入固定安全分流。
6. 越权访问：直接修改会话 ID，验证服务端是否阻止读取其他账户数据。
7. 历史与总结：结束会话并在重新登录后查看记录和总结。
8. 自动化测试：现场运行测试并展示结果。

## 七、加分项

- 完整 GAD-7 自评及趋势展示；
- 删除会话及相关音频数据；
- 用户对回复标记“有帮助/无帮助”，并影响后续策略；
- ASR 低置信度时进行二次确认；
- 用户可以编辑 Agent 选择的语音风格；
- 敏感数据加密、日志脱敏或审计机制。

## 八、交付物

1. 可运行的前端和后端源码；
2. 数据库初始化或迁移脚本；
3. README：启动方式、架构、数据模型、策略依据、安全边界和已知限制；
4. 原项目复用内容与本次新增/修改内容清单；
5. 至少五个规定测试及实际运行结果；
6. 验收场景的运行记录、截图或现场演示。
